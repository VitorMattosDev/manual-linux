60  Arrays indexados e associativos

O script de backup tinha uma variável de configuração no topo, e a ideia parecia boa:

EXCLUSOES="--exclude=/proc --exclude=/sys --exclude=/home/kali/Downloads"
rsync -a $EXCLUSOES /origem/ /destino/

Funcionou por meses. Quebrou no dia em que alguém acrescentou um diretório com espaço no nome:

EXCLUSOES="--exclude=/proc --exclude=/home/kali/Meus Documentos"

O rsync recebeu --exclude=/home/kali/Meus e, separadamente, Documentos — que ele interpretou como mais um caminho de origem. O backup passou a incluir o que devia excluir e a copiar um diretório inexistente, reclamando disso todas as noites num log que ninguém lia.

A tentação natural é pôr aspas: rsync -a "$EXCLUSOES". Isso piora. Agora o rsync recebe um único argumento gigante, com todos os --exclude grudados, e falha na hora.

O problema não tem solução dentro de uma variável de texto, e a razão é estrutural: uma cadeia de caracteres não guarda onde um item termina e o próximo começa. Ou você deixa o shell adivinhar pelos espaços — e ele erra em qualquer item que contenha espaço — ou você impede a divisão e perde a separação por completo. O shell tem um tipo de dado para isso, e é o assunto deste capítulo.

60.1 Um array preserva as fronteiras entre os itens

A mesma configuração, com o tipo certo:

EXCLUSOES=(
    --exclude=/proc
    --exclude=/sys
    "--exclude=/home/kali/Meus Documentos"
)
rsync -a "${EXCLUSOES[@]}" /origem/ /destino/

O rsync recebe exatamente três argumentos, o terceiro com o espaço intacto. Nenhuma adivinhação, nenhum IFS envolvido. E se o array estiver vazio, o rsync recebe zero argumentos extras em vez de um argumento vazio.

As formas de criar um array:

arr=(um dois tres)                  # literal
arr=()                              # vazio
declare -a arr                      # declaracao explicita
arr[0]=um; arr[5]=seis              # por indice, com buracos permitidos
arr+=(quatro)                       # acrescenta ao final

logs=( /var/log/*.log )             # de um glob -- cada arquivo e um item
mapfile -t linhas < arquivo.txt     # de um arquivo, uma linha por item
readarray -t linhas < arquivo.txt   # sinonimo de mapfile
IFS=: read -ra caminhos <<< "$PATH" # de uma cadeia, com separador escolhido

O mapfile -t merece destaque: o -t remove a quebra de linha de cada item, e o comando é bem mais rápido e mais seguro que um laço while read acumulando com +=. Para a saída de um comando, combine com a substituição de processo do Capítulo 58:

mapfile -t usuarios < <(cut -d: -f1 /etc/passwd)
echo "${#usuarios[@]} usuarios"

60.2 [@] contra [*]: a distinção que decide tudo

Acessar um elemento é simples; acessar o array inteiro tem quatro formas, e três delas estão erradas na maioria dos casos.

arr=(um "dois com espaco" tres)

echo "${arr[0]}"        # um -- indices comecam em ZERO
echo "${arr[-1]}"       # tres -- indice negativo conta do fim
echo "${#arr[@]}"       # 3 -- quantidade de elementos
echo "${#arr[0]}"       # 2 -- comprimento do PRIMEIRO ELEMENTO
echo "${!arr[@]}"       # 0 1 2 -- os indices existentes

Repare na diferença entre ${#arr[@]} e ${#arr[0]}: uma conta itens, a outra conta caracteres de um item. É uma fonte recorrente de confusão, e o [@] é o que faz a diferença.

O mesmo par @/* já apareceu em "$@" e "$*" no Capítulo 59 — não é coincidência: os parâmetros posicionais são um array, com a mesma semântica.

Para juntar com outro separador que não o do IFS, altere-o localmente:

arr=(alfa beta gama)
( IFS=,; echo "${arr[*]}" )     # alfa,beta,gama -- em subshell, sem afetar o resto

60.3 Fatias, buracos e a natureza esparsa dos índices

arr=(zero um dois tres quatro cinco)

echo "${arr[@]:2}"        # dois tres quatro cinco -- a partir do indice 2
echo "${arr[@]:1:3}"      # um dois tres -- 3 itens a partir do indice 1
echo "${arr[@]: -2}"      # quatro cinco -- espaco antes do menos e obrigatorio

O espaço em ${arr[@]: -2} não é opcional: sem ele, o :- é lido como o operador de valor padrão do Capítulo 62.

Um array de shell não é um vetor contíguo. Os índices são chaves de uma tabela, e apagar um elemento deixa um buraco:

arr=(a b c d)
unset 'arr[1]'
echo "${#arr[@]}"        # 3 -- restam tres elementos
echo "${!arr[@]}"        # 0 2 3 -- mas os indices sao 0, 2 e 3
echo "${arr[1]:-vazio}"  # vazio

Aspas em unset 'arr[1]' evitam que o [1] seja tratado como glob quando existir um arquivo chamado arr1 no diretório. Depois do unset, iterar de 0 até ${#arr[@]} menos um pula elementos e visita índices inexistentes. As duas formas corretas de percorrer:

for item in "${arr[@]}"; do ... done       # pelos VALORES, ignora buracos
for i in "${!arr[@]}"; do ... done         # pelos INDICES que existem

Para reindexar e eliminar os buracos, basta reconstruir: arr=("${arr[@]}").

60.4 Arrays associativos: chave de texto em vez de índice

A partir do Bash 4, o shell tem tabelas hash. A declaração é obrigatória e é o erro número um de quem começa:

declare -A porta          # SEM isto, o Bash trata como array indexado
porta[ssh]=22
porta[http]=80
porta[https]=443
porta=( [dns]=53 [smtp]=25 )       # tambem na criacao

echo "${porta[https]}"    # 443
echo "${!porta[@]}"       # as CHAVES: https smtp dns ssh http (ordem arbitraria)
echo "${porta[@]}"        # os VALORES
echo "${#porta[@]}"       # 5

Sem declare -A, porta[ssh]=22 faz o shell avaliar ssh como expressão aritmética — variável não definida vale zero — e você acaba com um array indexado onde tudo foi parar no índice 0, sobrescrevendo-se. Nenhum erro é emitido.

Percorrer um associativo é sempre pelas chaves, e quase sempre com ordenação explícita:

for servico in "${!porta[@]}"; do
    printf '%-8s %s\n' "$servico" "${porta[$servico]}"
done

# com ordem estavel
for servico in $(printf '%s\n' "${!porta[@]}" | sort); do
    printf '%-8s %s\n' "$servico" "${porta[$servico]}"
done

Chaves podem conter espaço, barra e quase qualquer coisa, desde que citadas: porta["dns reverso"]=53. Os usos típicos são contagem de ocorrências, deduplicação e tabelas de tradução:

# contar shells em uso -- o array associativo faz o papel do sort | uniq -c
declare -A contagem
while IFS=: read -r _ _ _ _ _ _ shell; do
    (( ++contagem["$shell"] ))
done < /etc/passwd

for sh in "${!contagem[@]}"; do
    printf '%4d  %s\n' "${contagem[$sh]}" "$sh"
done | sort -rn

Repare que (( ++contagem["$shell"] )) funciona mesmo para uma chave que ainda não existe: em contexto aritmético, ausente vale zero.

Para deduplicar preservando a ordem original, o associativo serve de conjunto:

declare -A visto
unicos=()
for item in "${lista[@]}"; do
    [[ -n ${visto[$item]:-} ]] && continue
    visto[$item]=1
    unicos+=("$item")
done

60.5 Construir linha de comando é o uso que mais salva

Este é o padrão que resolve o problema da abertura em qualquer contexto — flags condicionais, caminhos com espaço, opções vindas de variável:

argumentos=( -a --delete )
[[ -n ${VERBOSE:-} ]]  && argumentos+=( -v )
[[ -n ${SIMULAR:-} ]]  && argumentos+=( --dry-run )
[[ -n ${LIMITE:-} ]]   && argumentos+=( --bwlimit="$LIMITE" )

for dir in "${EXCLUSOES[@]}"; do
    argumentos+=( --exclude="$dir" )
done

rsync "${argumentos[@]}" "$ORIGEM/" "$DESTINO/"

Nada aqui depende do IFS, nenhum caminho precisa estar livre de espaços, e acrescentar uma opção é uma linha. A alternativa com eval — que ainda aparece em scripts antigos — reintroduz a injeção de comando discutida no Capítulo 53 e não resolve nada que o array não resolva.

Uma ressalva de versão: sob set -u (Capítulo 57), expandir um array vazio com "${arr[@]}" era erro fatal até o Bash 4.3. Em Bash 4.4 e posteriores — o que inclui qualquer Kali atual — o array vazio expande para nada, corretamente. Se o script precisa rodar em sistemas antigos, a defesa é "${arr[@]:-}" ou testar (( ${#arr[@]} )) antes.

Para depurar o que exatamente vai ser executado, imprima com %q, que mostra as fronteiras:

printf 'comando: rsync'; printf ' %q' "${argumentos[@]}"; printf '\n'

60.6 O que arrays não fazem

Não existe array de arrays. O shell tem uma dimensão só, e não há sintaxe para aninhar. As saídas usuais são combinar chave e índice num associativo (matriz["2,3"]=valor), guardar cada linha como texto com um separador escolhido, ou aceitar que o problema pede outra linguagem — Python ou awk, tema do Volume 11.

Arrays não são passados nem devolvidos por funções. Uma função recebe palavras, e o array vira palavras ao ser expandido. As três formas de contornar:

# 1. expandir na chamada e reconstruir dentro (perde o nome, preserva os itens)
processar() { local -a itens=( "$@" ); echo "${#itens[@]} itens"; }
processar "${lista[@]}"

# 2. nameref, quando a funcao precisa MODIFICAR o array do chamador
acrescentar() { local -n ref="$1"; shift; ref+=( "$@" ); }
acrescentar lista novo1 novo2

# 3. imprimir com separador nulo e ler de volta (atravessa ate subshell)
mapfile -t -d '' copia < <(printf '%s\0' "${origem[@]}")

declare -A dentro de função cria variável local por padrão no Bash 4.2 e posteriores. Para um associativo global declarado dentro de uma função, use declare -gA.

60.7 🐉 No Kali

  • Lista de alvos autorizados é array, nunca cadeia de texto. ALVOS=( 10.10.10.5 10.10.10.7 "servidor de teste.lab" ) sobrevive a nome com espaço e a lista vazia; ALVOS="10.10.10.5 10.10.10.7" depende do IFS e falha em silêncio no primeiro item atípico. Como o laço sobre alvos é justamente onde o filtro de escopo se aplica (Capítulo 58), o tipo de dado errado aqui vira alvo varrido fora do escopo contratado — crime pela Lei 12.737/2012.
  • Opções de nmap, gobuster e hydra montadas condicionalmente pedem array. Um wrapper que decide entre -sS e -sT conforme o privilégio, que acrescenta --max-rate quando há limite contratado e que insere o arquivo de saída só às vezes é exatamente o caso do argumentos+=( ... ). Com string e eval, uma senha ou um caminho com aspas na lista de opções vira execução de comando.
  • Array associativo é a estrutura natural para o mapa porta-serviço e para agregar resultados. Depois de percorrer a saída de uma varredura, declare -A achados; achados["$ip:$porta"]="$banner" dá deduplicação de graça e consulta direta, sem reprocessar arquivo. Lembre que a ordem de ${!achados[@]} é arbitrária: relatório sai por sort.
  • mapfile -t sobre arquivo de alvos é mais seguro que for alvo in $(cat alvos.txt). O segundo divide por espaço, expande glob e engasga em linha com comentário contendo *. O primeiro preserva a linha inteira; filtre comentários e linhas vazias com [[ $alvo =~ ^[[:space:]]*(#|$) ]] && continue dentro do laço.
  • Arquivos de wordlist do Kali não cabem em array. /usr/share/wordlists/rockyou.txt tem mais de 14 milhões de linhas; mapfile carregaria tudo na memória do shell, com sobrecarga de várias dezenas de bytes por item. Wordlist se processa em fluxo, com while IFS= read -r, ou se entrega direto à ferramenta que sabe lidar com ela. Array é para dezenas ou milhares de itens, não para milhões.

Nota sobre a família RHEL. Arrays indexados existem no Bash desde a versão 2 e não variam entre distribuições. Arrays associativos exigem Bash 4 (2009) e portanto estão presentes em qualquer RHEL 7 ou posterior; o mapfile -d, usado acima com o byte nulo, exige Bash 4.4 — RHEL 8 em diante, e todo Kali atual. A divergência que realmente morde é outra: arrays não são POSIX. Um script com #!/bin/sh que use arr=(...) funciona em RHEL, onde /bin/sh é o Bash, e falha no dash do Debian e do Kali com um Syntax error: "(" unexpected. Se o script usa array, o shebang é #!/usr/bin/env bash, sem exceção.

60.8 🧪 Laboratório

Roteiro para uma VM do Kali, contido em ~/lab-arrays.

  1. Reproduza o bug da abertura com uma string.

    mkdir -p ~/lab-arrays && cd ~/lab-arrays
EXCLUSOES="--exclude=/proc --exclude=/home/Meus Documentos"
printf '[%s]\n' $EXCLUSOES
echo "--- com aspas ---"
printf '[%s]\n' "$EXCLUSOES"

    Esperado: sem aspas, quatro linhas — Meus e Documentos separados. Com aspas, uma linha só, com tudo grudado. Nenhuma das duas é o que o rsync precisa.

  2. Corrija com array.

    EXCLUSOES=( --exclude=/proc "--exclude=/home/Meus Documentos" )
printf '[%s]\n' "${EXCLUSOES[@]}"
echo "quantidade: ${#EXCLUSOES[@]}"

    Esperado: exatamente duas linhas, a segunda com o espaço preservado, e quantidade: 2.

  3. Percorra a matriz de expansões da figura.

    arr=(um "dois com espaco" tres)
echo '--- "${arr[@]}" ---'; printf '[%s]\n' "${arr[@]}"
echo '--- "${arr[*]}" ---'; printf '[%s]\n' "${arr[*]}"
echo '--- ${arr[@]} ---';   printf '[%s]\n' ${arr[@]}
echo '--- ${arr[*]} ---';   printf '[%s]\n' ${arr[*]}

    Esperado: 3, 1, 4 e 4 linhas, na ordem. É a Figura 60.1 em execução.

  4. Separe contagem de itens de comprimento de item.

    arr=(alfa beta "gama delta")
echo "itens no array:        ${#arr[@]}"
echo "caracteres em arr[0]:  ${#arr[0]}"
echo "caracteres em arr[2]:  ${#arr[2]}"

    Esperado: 3, 4 e 10.

  5. Crie um buraco e veja o laço ingênuo falhar.

    arr=(a b c d)
unset 'arr[1]'
echo "tamanho: ${#arr[@]}   indices: ${!arr[@]}"
echo "--- laco por indice numerico (ERRADO) ---"
for (( i = 0; i < ${#arr[@]}; i++ )); do echo "[$i]=${arr[$i]:-<vazio>}"; done
echo "--- laco por indices existentes (CERTO) ---"
for i in "${!arr[@]}"; do echo "[$i]=${arr[$i]}"; done

    Esperado: o laço numérico imprime um <vazio> no índice 1 e nunca alcança o d no índice 3. O correto imprime os três elementos reais.

  6. Reindexe.

    arr=( "${arr[@]}" )
echo "indices apos reindexar: ${!arr[@]}"

    Esperado: 0 1 2, sem buracos.

  7. Fatie.

    n=(zero um dois tres quatro cinco)
echo "a partir de 2 : ${n[@]:2}"
echo "3 itens do 1  : ${n[@]:1:3}"
echo "ultimos 2     : ${n[@]: -2}"
echo "ultimo item   : ${n[-1]}"

    Esperado: as quatro fatias descritas. Remova o espaço antes do -2 e veja a expansão mudar de sentido.

  8. Veja o que acontece sem declare -A.

    unset mapa
mapa[ssh]=22
mapa[http]=80
declare -p mapa

    Esperado: declare -a mapa=([0]="80"). Sem a declaração, ssh e http foram avaliados como aritmética, ambos valeram zero, e o segundo sobrescreveu o primeiro. Nenhum erro foi emitido.

  9. Agora com a declaração.

    unset mapa; declare -A mapa
mapa[ssh]=22; mapa[http]=80; mapa["dns reverso"]=53
declare -p mapa
for k in "${!mapa[@]}"; do printf '%-14s %s\n' "$k" "${mapa[$k]}"; done

    Esperado: três pares distintos, com a chave contendo espaço intacta. Rode o laço duas vezes e note que a ordem pode não ser a de inserção.

  10. Conte com um associativo.

    declare -A contagem
while IFS=: read -r _ _ _ _ _ _ shell; do
    (( ++contagem["$shell"] ))
done < /etc/passwd
for sh in "${!contagem[@]}"; do printf '%4d  %s\n' "${contagem[$sh]}" "$sh"; done | sort -rn

    Esperado: a distribuição de shells do sistema, do mais usado ao menos. No Kali, /usr/sbin/nologin costuma liderar.

  11. Monte uma linha de comando condicional e inspecione-a.

    VERBOSE=1; LIMITE=2000
argumentos=( -a --delete )
[[ -n ${VERBOSE:-} ]] && argumentos+=( -v )
[[ -n ${LIMITE:-}  ]] && argumentos+=( --bwlimit="$LIMITE" )
argumentos+=( "--exclude=/home/Meus Documentos" )

printf 'rsync'; printf ' %q' "${argumentos[@]}"; printf ' ORIGEM/ DESTINO/\n'

    Esperado: a linha completa, com o --exclude do caminho com espaço citado pelo %q. É a forma de conferir a lista antes de trocar o printf pelo rsync de verdade.

  12. Carregue um arquivo com mapfile e devolva um array de uma função.

    printf 'alvo um\nalvo dois\n# comentario\n\nalvo tres\n' > alvos.txt
mapfile -t alvos < alvos.txt
echo "lidos: ${#alvos[@]}"

filtrar() {
    local -n destino="$1"; shift
    local linha
    destino=()
    for linha in "$@"; do
        [[ $linha =~ ^[[:space:]]*(#|$) ]] && continue
        destino+=( "$linha" )
    done
}
filtrar validos "${alvos[@]}"
printf '[%s]\n' "${validos[@]}"
cd ~ && rm -rf ~/lab-arrays

    Esperado: lidos: 5 (incluindo comentário e linha vazia) e três itens válidos ao final, cada um com o espaço interno preservado.

60.9 Resumo

  • Cadeia de texto não guarda fronteiras entre itens. Lista de caminhos, de alvos ou de opções de comando é array — a alternativa depende do IFS e quebra no primeiro item com espaço.
  • "${arr[@]}" com aspas é a forma correta em quase todo uso: produz um argumento por elemento. "${arr[*]}" junta tudo numa palavra só e serve para exibir. Sem aspas, as duas viram a mesma coisa e desfazem o array.
  • ${#arr[@]} conta elementos; ${#arr[0]} conta caracteres do primeiro. E ${!arr[@]} lista os índices que realmente existem.
  • Arrays do shell são esparsos. unset 'arr[1]' deixa um buraco, então iterar por índice numérico pula elementos. Percorra por "${arr[@]}" ou por "${!arr[@]}"; reindexe com arr=("${arr[@]}").
  • Array associativo exige declare -A antes do primeiro uso. Sem isso, a chave de texto é avaliada como aritmética, vale zero, e todos os valores se sobrescrevem no índice 0 sem nenhum aviso.
  • A ordem de ${!assoc[@]} é a da tabela hash, não a de inserção nem a alfabética. Ordene explicitamente quando a saída importar.
  • Montar linha de comando com argumentos+=( ... ) e chamar cmd "${argumentos[@]}" resolve flags condicionais e caminhos com espaço sem eval. Confira com printf ' %q' antes de executar.
  • Arrays não são POSIX e não aninham. Exigem #!/usr/bin/env bash, e não são passados a funções — expanda com "${arr[@]}" e reconstrua, ou use local -n quando a função precisar modificar o original.
